# PantryFlow：社区食品库存调度系统

PantryFlow 是一个使用 MoonBit 实现的社区食品库存调度系统，聚焦临期物资分配与损耗模拟。它帮助运营人员在不收集受助者个人信息的前提下，按物资保质期、站点冷藏能力、品类需求和服务优先级生成可解释的分配计划。

> PantryFlow 是运营决策支持工具，不替代食品安全法规、人工质检、食品召回、营养建议或任何监管认证。

## 能力

- 对批次、站点和聚合需求进行确定性校验；
- 使用 FEFO（先到期先分配）规则生成分配建议；
- 考虑常温、冷藏、冷冻容量及预制餐接收能力；
- 标记无法满足的最低需求、未分配临期物资和容量风险；
- 按日模拟过期、损耗、库存余额与未满足需求；
- 输出可追溯的分配原因和评分，便于人工复核。

## 边界

项目只处理匿名的汇总物资和需求数据，不提供：捐赠撮合、志愿者调度、身份认证、支付、地图导航、真实食品安全判定或监管申报。

## 本地运行

需要 MoonBit `0.1.20260920` 或更新版本。

```powershell
moon check
moon test src
moon run cmd/main
```

## 核心模型

| 模型 | 用途 |
|---|---|
| `FoodLot` | 带品类、存储条件、到期日和数量的库存批次 |
| `DistributionSite` | 分发站点的优先级和分温区容量 |
| `DemandLine` | 某站点在某日提出的聚合品类需求 |
| `PolicyProfile` | 临期阈值、惩罚项和替代规则的版本化配置 |
| `Allocation` | 批次到需求的计划量、原因和分数 |

## 示例场景

以苹果、牛奶、面包三类临期库存和两个站点为例：

1. 导入库存批次、站点容量与需求；
2. 运行分配器；
3. 优先分配最接近到期日且满足站点能力的物资；
4. 生成未满足需求和损耗风险清单；
5. 运行 14 天模拟，比较计划分配和自然损耗。

示例数据全部为虚构数据，不包含任何个人信息或真实受助者资料。

## 质量保证

核心算法包含白盒测试，覆盖数量下界、FEFO 顺序、站点容量、站点能力限制、输入校验、过期模拟和冷冻保全规则。

持续集成将执行：

```powershell
moon check
moon test
moon fmt --check
```
